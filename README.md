# 数独

HTML + CSS + JavaScript だけで作った数独ゲーム。
ライブラリもビルドも不要で、`index.html` をダブルクリックすればすぐ遊べます。

**公開URL： https://nabe-chan-1973.github.io/sudoku/**

---

## スマホに入れる（PWA）

Android / iPhone のブラウザで上の URL を開き、

- **Android (Chrome)**: 画面下の**緑の「ホーム画面にインストール」ボタン**を押す
- **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」

これでホーム画面にアイコンが並び、タップすると**ブラウザのバーが消えた全画面**で起動します。
Service Worker がファイルを端末に保存するので、**圏外・機内モードでも遊べます**。

更新したいときは `git push` するだけ。次にアプリを開いたときに自動で新しくなります
（ストアの審査もインストールし直しも不要）。

### インストールボタンが出ないとき

緑のボタンは、Chrome が「インストール可能」と判定したときだけ現れます。
出ない場合、原因はだいたい次のどれかです。

| 症状 | 原因 | 対処 |
|---|---|---|
| ボタンが出ない | **アプリ内ブラウザ**で開いている（LINE・X・Gmail のリンクから飛ぶとこうなる） | メニューから「ブラウザで開く」 |
| ボタンが出ない | **すでにインストール済み** | ホーム画面を確認。入れ直すなら一度削除 |
| ボタンが出ない | シークレットモード | 通常モードで開く |
| ボタンが出ない | 読み込み直後でまだ判定前 | 数秒待つ / 一度リロード |

Chrome のメニューから入れることもできますが、現在の Android Chrome には
**「アプリをインストール」という項目はありません**。「**ホーム画面に追加**」に統合され、
押すと出るシートで「インストール」か「ショートカット」を選ぶ形になっています。
（ショートカットを選ぶと、ただのブラウザ用リンクになり全画面になりません）

## 遊びかた（パソコン）

`index.html` をダブルクリックしてブラウザで開くだけ。

### 操作

| やりたいこと | スマホ | パソコン |
|---|---|---|
| マスを選ぶ | タップ | 矢印キー / クリック |
| 数字を入れる | 下の数字ボタン | `1`〜`9` |
| 数字を消す | 「消す」 | `Backspace` |
| メモ（小さい数字）| 「メモ」を ON にしてから数字 | `M` で切替 |
| 一手戻す | 「戻す」 | — |
| 答えを1マス教えてもらう | 「ヒント」 | — |

### 仕組みで気を配ったところ

- 同じ数字をもう一度押すと消えます
- 数字を確定すると、同じ行・列・ブロックのメモから自動でその数字が消えます
- 間違った数字は**赤**、ヒントで出た数字は**緑**、自分で入れた数字は**青**
- ルール違反（同じ列に同じ数字など）のマスは背景がピンクになります
- 途中でブラウザを閉じても、次に開いたとき**続きから**遊べます
- 端末がダークモードなら自動でダークテーマになります

## ファイルの構成

役割ごとに分けてあります。**どこを直せばいいか迷わない**のが狙いです。

```
数独/
├── index.html      ← 画面の骨組み。全部をつなぐ入れ物
├── style.css       ← 見た目（色・大きさ・並べかた）
├── sudoku.js       ← 数独の「頭脳」。問題を作る・答えを数える
├── app.js          ← 「画面」担当。タップを受けて盤面を描く
│
├── manifest.json   ← アプリ名・アイコン・全画面表示の設定（PWA）
├── sw.js           ← オフライン対応（Service Worker）
└── icons/          ← ホーム画面に並ぶアイコン
```

### なぜ sudoku.js と app.js を分けたか

`sudoku.js` には **HTML の話が一行も出てきません**。
純粋に「81個の数字の配列」を計算するだけの部品です。

こう分けておくと、

- **テストしやすい**（画面を開かなくても Node で動かして検証できる）
- **作り直しやすい**（将来 Flutter で作るとき、このロジックの考えかたをそのまま移植できる）
- **バグの場所が分かりやすい**（見た目が変なら app.js か style.css、問題そのものが変なら sudoku.js）

## ロジックの中身（学習メモ）

### 1. 答えを作る — バックトラック法

空の盤面に、左上から順に「置ける数字」を入れていきます。
行き詰まったら**一つ戻して別の数字で試し直す**。これがバックトラック。

人間が数独を解くときの「とりあえず入れてみて、ダメなら戻る」と同じ考えかたです。

### 2. 問題を作る — 削って、確かめる

1. まず完成形（答え）を作る
2. マスを1つずつ空白にしていく
3. 空白にした結果、**答えが2通り以上になってしまったら元に戻す**

良い数独は「答えがぴったり1通り」でなければいけません。
2通りあったらどっちが正解か決められない＝欠陥問題です。

### 3. 速くする工夫 — 候補が少ないマスから埋める

最初は「左上から順に」埋めていましたが、難易度「鬼」の生成に **1秒** かかっていました。

これを「**入る数字の候補が一番少ないマスから埋める**」に変えたら **23ms** になりました（45倍速）。
人間も「ここは 3 か 7 しかない」というマスから手をつけますよね。同じ発想です。

`sudoku.js` の `pickBestCell()` がその部分です。

### 生成にかかる時間（実測）

| 難易度 | 空白の数 | 1問あたり |
|---|---|---|
| かんたん | 40 | 1ms |
| ふつう | 48 | 2ms |
| むずかしい | 54 | 10ms |
| 鬼 | 56 | 20ms |

## 開発中に使うもの

ブラウザで直接開くだけでも動きますが、ローカルサーバーを立てると
スマホの実機からも同じ Wi-Fi 経由で確認できます。

```bash
python -m http.server 8765
```

ロジックだけをテストしたいとき（画面を開かずに検証）:

```bash
node -e "const S=require('./sudoku.js'); console.log(S.createPuzzle('hard').puzzle.join(''))"
```

## 更新のしかた

ファイルを直して push すれば、それだけで反映されます。

```bash
git add -A && git commit -m "説明" && git push
```

`sw.js` の `CACHE` の名前（`sudoku-v1`）を変えると、古いキャッシュを確実に捨てさせられます。
普段は不要ですが、「更新したのにスマホが古いまま」のときはここを `sudoku-v2` に上げてください。

## なぜ Capacitor や Android Studio を使わなかったか

最初は「Capacitor で包んで APK を作る」案を考えましたが、
**Android Studio のインストールに約10GB** が必要でした。

PWA なら、

- インストール不要（既にあるブラウザが実行環境）
- ストア審査なし、APK の配布作業なし
- 更新は `git push` だけで全端末に反映
- Android も iPhone も同じものが動く

数独のように**画面とロジックだけで完結するゲーム**なら、PWA で十分すぎます。
APK が要るのは、カメラ・位置情報・通知・バックグラウンド処理など
ブラウザでは届かない機能を使いたくなったときです。
